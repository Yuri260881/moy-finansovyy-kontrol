# Мой финансовый контроль

Личное русскоязычное PWA для платежей ИП, зарплат, налогов и отчетности. Клиент работает на GitHub Pages, данные и серверные функции — в вашем Supabase. Финансовые суммы в PostgreSQL имеют тип `numeric(14,2)`. Фактические расходы считаются исключительно по таблице `payments` и дате оплаты.

## Структура

- `src/` — React, TypeScript, адаптивный интерфейс, учет и тесты расчетов.
- `supabase/migrations/` — таблицы, ограничения, RLS, автоматическое создание пяти объектов и трех сотрудников, журнал изменений.
- `supabase/functions/` — OAuth Google, синхронизация календаря, почта/Telegram и удаление аккаунта.
- `.github/workflows/pages.yml` — сборка и публикация Pages.
- `.github/workflows/reminders.yml` — почасовая серверная проверка напоминаний.
- `scripts/restore.mjs` — восстановление полного экспорта в тот же аккаунт.

## Локальный запуск

Требуются Node.js 22+, npm, аккаунт Supabase. Выполните:

```bash
npm ci
cp .env.example .env.local
# В .env.local впишите VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY и VITE_LOGIN_EMAIL
npm run dev
```

Откройте адрес Vite. `npm test` проверяет учет частичной оплаты и исключение отчетов из денежных планов, `npm run build` собирает PWA. Публикация и рабочие интеграции требуют шагов ниже.

## 1. Supabase

1. Создайте проект Supabase. В **Project Settings → API** скопируйте URL и **publishable/anon key**. Это публичные значения для `VITE_`; **service role/secret key не помещайте в `.env.local` фронтенда**.
2. В **Authentication → Providers → Email** оставьте вход с паролем. В **Authentication → Users → Add user** создайте единственного пользователя с техническим идентификатором `owner@fincontrol.example` и задайте пароль самостоятельно в интерфейсе Supabase. Подтвердите запись при создании, затем отключите открытую регистрацию новых пользователей в настройках Auth. Этот адрес используется внутри Supabase как идентификатор; на экране входа запрашивается только пароль. В **URL Configuration** укажите Site URL вида `https://USERNAME.github.io/REPOSITORY/`. Для восстановления пароля используйте панель администратора Supabase; общедоступной кнопки восстановления здесь нет.
3. Установите [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started) и выполните:

```bash
npx supabase login
npx supabase link --project-ref PROJECT_REF
npx supabase db push
npx supabase functions deploy google-oauth
npx supabase functions deploy calendar-sync
npx supabase functions deploy reminders
npx supabase functions deploy account-data
```

4. Миграции создают приватный bucket `receipts`, RLS и начальные записи при создании пользователя. Ему сразу доступны Взлетная, Демократическая, Свердлова, Вардане, Костромская и три карточки сотрудников. Реальные суммы и даты остаются пустыми.
5. В **Edge Functions → Secrets** или CLI задайте секреты. Пример: `npx supabase secrets set TOKEN_ENCRYPTION_KEY=... CRON_SECRET=...`. Ключ шифрования токенов — длинная случайная строка; сохраните его отдельно, потеря сделает прежние Google refresh токены нечитаемыми. `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` предоставляются платформой для функций.

### Права доступа

Каждая финансовая таблица имеет RLS по `auth.uid()`. `connections` с Google refresh токеном и Telegram chat ID недоступна браузеру напрямую; функции читают ее по service role после проверки пользовательского JWT. Квитанции лежат в приватном bucket с путем, начинающимся с UUID владельца. `audit_log` доступен пользователю только для чтения. Сумму оплаты вносит серверная RPC под блокировкой строки, не позволяя переплатить план или изменить чужую запись.

## 2. Google Calendar

1. В Google Cloud создайте проект, включите **Google Calendar API**, настройте экран согласия OAuth (для режима Testing добавьте себя в тестовые пользователи).
2. Создайте OAuth Client ID типа **Web application**. Authorized redirect URI: `https://PROJECT_REF.supabase.co/functions/v1/google-oauth/callback`.
3. В Supabase Edge Function Secrets задайте `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `TOKEN_ENCRYPTION_KEY`, `APP_ORIGIN=https://USERNAME.github.io`, `APP_BASE_PATH=/REPOSITORY/`.
4. В приложении откройте **Настройки → Подключить Google Календарь**, войдите, выберите календарь и нажмите **Сохранить и синхронизировать**. Повторная синхронизация обновляет события по таблице `calendar_events`, отмененные удаляет. Для автономного импорта доступен `.ics`.

OAuth refresh токен шифруется AES-GCM и хранится только на сервере. После потери ключа шифрования подключите календарь заново. После сохранения изменений приложение синхронизирует подключённый календарь. Кнопка повторной синхронизации позволяет восстановить связь после сетевой ошибки. Для дат платежей создаются приватные события на 09:00–09:15 в часовом поясе пользователя (это время уведомления, а не юридический срок). Неоплаченные события получают popup в день срока и до четырёх предварительных напоминаний; выполненные — без напоминаний. Для доставки включите уведомления Google Календаря на телефоне. Уже синхронизированные события напоминают при закрытом приложении. Новые события и правки требуют успешной синхронизации; фонового чтения изменений базы пока нет.

## 3. Telegram и почта

1. Создайте бота через BotFather. Задайте `TELEGRAM_BOT_TOKEN` как секрет функции Supabase, не добавляйте его в репозиторий. Напишите боту `/start`, получите свой числовой chat ID через `getUpdates` API бота и введите его в настройках приложения. Включите канал Telegram.
2. Для почты создайте API ключ Resend и подтвердите домен отправителя. Укажите серверные `MAIL_PROVIDER_API_KEY` и `MAIL_FROM`, затем включите почту в настройках. Получатель — почта аккаунта.
3. Задайте одинаковый `CRON_SECRET` в Supabase Edge Function Secrets и GitHub **Settings → Secrets and variables → Actions → Repository secrets**. Workflow `reminders.yml` запускается ежечасно и вызывает серверную функцию. В GitHub repository variable задайте `VITE_SUPABASE_URL`.
4. Установите часовой пояс пользователя. Расписание проверяется по локальному дню пользователя. Для каждого срока и канала отправка фиксируется в `reminder_log`; после полной оплаты новые напоминания не отправляются. Ошибки доставки видны в логах Edge Functions; повторный часовой запуск попробует отправить снова.

Для уведомлений во внутреннем журнале приложение должно хотя бы раз открыть настройки после серверной проверки; сам сервер работает при закрытом приложении. Почасовое расписание GitHub Actions может выполняться с задержкой, поэтому не полагайтесь на точную минуту доставки.

## 4. GitHub Pages

1. Создайте **приватный или публичный** репозиторий GitHub и отправьте туда исходники. Пример:

```bash
git init
git add .
git commit -m "Initial financial control app"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

2. В **Settings → Secrets and variables → Actions → Variables** задайте `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` и `VITE_LOGIN_EMAIL=owner@fincontrol.example`. Эти значения попадают в публичную сборку; никогда не используйте здесь настоящий пароль.
3. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**. После push в `main` workflow соберет сайт с базовым путем `/REPOSITORY/` и опубликует его. Для установки на телефон откройте сайт по HTTPS и используйте «Добавить на главный экран».
4. Финансовая база не публикуется вместе с сайтом. Публичные `VITE_` значения не являются секретами; безопасность обеспечивают Auth и RLS.

## Ежедневная работа

- **Новый платеж:** укажите название, объект, категорию, сумму, дату и повторение. Генерация создает экземпляры до 24 месяцев вперед, уникальные по шаблону и сроку. После редактирования сотрудника старые будущие начисления отменяются, а новые создаются по новым суммам.
- **Оплата:** в карточке обязательства укажите фактическую сумму и дату. Частичная оплата уменьшает остаток; расходы аналитики относятся к месяцу фактического перевода. История видна в карточке, изменения обязательств — в `audit_log`.
- **Зарплата:** укажите зарплату на руки, аванс и дни выплаты у сотрудника. Два независимых шаблона создают аванс и окончательный расчет. НДФЛ и взносы вводятся отдельно.
- **Отчет:** создайте обязательство в разделе налогов, вручную проверьте срок и последовательно отмечайте подготовку, отправку, принятие. Приложение не содержит придуманного календаря ФНС или СФР и не рассчитывает удержания.
- **Массовый импорт:** файл `.xlsx` или `.csv` с заголовками `Название`, `Дата` (`ГГГГ-ММ-ДД`), `Сумма`, `Объект` (точное имя). Импорт создает разовые платежи; проверьте файл до повторного импорта. CSV/Excel/PDF отчет строится по фактическим оплатам выбранного периода.

## Корзина ошибочных платежей

Откройте платеж → «Удаление ошибочной записи» → «Удалить этот платёж» либо «Удалить всю серию». Удаление всей серии останавливает её шаблон. Подтверждение объясняет, что связанные фактические оплаты исключаются из аналитики. Записи, оплаты, квитанции и аудит сохраняются; генератор не создаёт удалённые экземпляры повторно, поскольку их уникальные ключи остаются в базе.

В разделе «Платежи → Корзина» можно восстановить отдельную запись вместе с оплатами. Восстановление не запускает остановленный шаблон автоматически. После удаления подключённый Google Календарь очищает соответствующие события при синхронизации. Для установки примените миграцию `202610220008_obligation_trash.sql` и обновите функции `reminders`, `calendar-sync`. Транзакционный SQL-тест `supabase/tests/trash.sql` проверяет удаление одного экземпляра, всей серии, сохранение оплат, запрет оплаты из корзины и изоляцию пользователей; он выполняется с `ROLLBACK`.

## Экспорт, восстановление, удаление

В настройках скачайте JSON с таблицами и содержимым квитанций; файл может быть большим и содержит конфиденциальные данные. Храните его защищенно. Токены интеграций в экспорт не включаются. Восстановление выполняется **в тот же аккаунт** из доверенной локальной среды, после создания проекта и применения миграций:

```bash
SUPABASE_URL=https://PROJECT_REF.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY \
node scripts/restore.mjs fincontrol-backup.json USER_UUID
```

Не запускайте это в браузере или GitHub Actions с публичными логами. После восстановления заново подключите Google и каналы уведомлений. Удаление аккаунта в настройках удаляет строки и квитанции. Дополнительно Supabase предоставляет управляемые резервные копии в зависимости от тарифного плана; пользовательский JSON позволяет независимо перенести данные.

## Проверка сценариев

`npm test && npm run build` — автоматические проверки и производственная сборка. После настройки Supabase проверьте вручную: вход по паролю и пять объектов; ежемесячная аренда Взлетной; частичная и полная оплата с изменением показателей; зарплата трех сотрудников; налог и отчет; просмотр месяца/недели/дня/списка; запуск `reminders` и запись в журнал; Google OAuth и повторная синхронизация; экспорт и восстановление в тестовом проекте; открытие на телефоне.

Ограничения: backend не получится запустить без собственного проекта Supabase и сторонних ключей; периодические проверки GitHub Actions не гарантируют доставку в точную минуту; налоговые сроки требуют ручного ввода и проверки у бухгалтера.

3. Создайте OAuth client типа Web application. Redirect URI: `https://aranphbxcaitzlzttkao.supabase.co/functions/v1/google-oauth/callback`.
